# RM-08 Deviation Record

Each entry gives what changed from `PROTOCOL.md`, when it was decided relative to the results, and what it affects.

| ID | Deviation | Decided | Consequence |
|---|---|---|---|
| DEV-01 | The three PMLR repositories and the JOSS repository were cloned (blob-less) and their file lists inspected before the protocol was committed. The metadata of one non-selected ICML paper (aamand23a) was displayed while checking the repository format. | Before selection | No pilot document was selected, opened or processed before the protocol commit (268f90d). Selection is seeded and deterministic, so the inspection could not influence which papers were drawn. |
| DEV-02 | None of the five ICML papers has a PDF outline. Instead of manual transcription (protocol §4), G1 for these papers uses a typographic rule: lines whose first span is 12 pt bold (ICML template heading font) and that begin with a section number or appendix letter. | After selection, before any MetaSense run | The rule is more reproducible than manual transcription and still independent of MetaSense's rules. Wrapped long titles keep only their first line, so matching uses the first words of each title. |
| DEV-03 | A sensitivity condition B2 was added: `pdftotext` in its default reading-order mode, next to the protocol's `pdftotext -layout` (B). `-layout` keeps two-column pages side by side on one line, which could make B fail for a reason unrelated to the detector. | Before any MetaSense run | B stays the pre-registered comparison. B2 is reported separately as a sensitivity check and is not used to pass any decision rule. |
| DEV-04 | Installing tag v0.2.1 non-editably from `git archive` silently installed v0.2.0 code from the committed `build/` directory (new defect D-09, `evidence/defect_repro/D09_tag_install_stale_build.txt`). The frozen reference was installed after deleting `build/` from the archive, with the pinned `requirements.txt`. | Before any MetaSense run | The reference under test is the v0.2.1 source (`metasense version` → 0.2.1, recorded in `run_environment.json`). The tag itself still needs a corrected release (v0.2.2). |
| DEV-05 | A citation-relevance audit (first evidence citation for C2, C3 and C4 in every document, 36 items, labelled relevant / partial / spurious) was added **after** the M1–M7 results were seen, because M7 showed control papers scoring higher than empirical papers. | After results | Exploratory and post hoc; AI-labelled and pending student verification (`labels/citation_relevance_audit.csv`). It explains M7 but is not used in any decision rule. |
| DEV-06 | Matching rules were fixed in code before analysis but not spelled out in the protocol. M3 counts a detected heading as matching a G1 heading when their first min(4, length) normalised words agree. M2 is stricter: the first four G1 words must start a single extracted line. | Written with the analysis script after the condition outputs existed, before any metric was computed | A heading split over two lines can count for M3 but not for M2. This explains why E1 recall (62/62) exceeds E1 recoverability (60/62). |
| DEV-07 | `analyze_pilot.py` computed D4 on 7 empirical papers, leaving out the ambiguous paper (bhattacharjee23a), while PROTOCOL.md §7 specifies 8. Found in the independent verification of the report. | After results | The report gives the pre-registered 8-paper values: 4/8 = 0.50 if the ambiguous paper counts as having methodology, 5/8 = 0.625 if not. The 7-paper value (0.571) is kept as recorded in `summary.json`. D4 fails on every version. |
